# 第三册：SLAM、导航与感知融合

## 第 1 章：状态估计问题

移动机器人需要回答三个问题：我在哪里、环境是什么样、下一步如何安全到达目标。定位和建图负责前两个问题，导航负责第三个问题。

机器人状态通常写为：

$$x_t=[p_x,p_y,\theta,v_x,v_y,\omega,\cdots]^T$$

不同系统状态维度不同。二维移动机器人可能只估计平面位姿和速度；无人机还需要三维位置、姿态、速度和 IMU 偏置。

状态估计包含两步：

1. **预测**：根据上一状态和控制输入推测当前状态。
2. **更新**：利用传感器测量修正预测。

写成概率形式：

$$p(x_t|z_{1:t},u_{1:t})$$

$u$ 是控制或运动信息，$z$ 是观测。滤波的目标是维护当前状态的后验分布，而不是只输出一个看起来平滑的轨迹。

### 运动模型

差速机器人在短时间 $\Delta t$ 内可近似：

$$
\begin{aligned}
x_{t+1}&=x_t+v_t\cos\theta_t\Delta t\\
y_{t+1}&=y_t+v_t\sin\theta_t\Delta t\\
\theta_{t+1}&=\theta_t+\omega_t\Delta t
\end{aligned}
$$

这是模型，不是真理。轮胎打滑、地面不平、控制延迟都会造成偏差，所以还要加入过程噪声。

### 可观测性

不是所有状态都能从当前传感器唯一推断。例如只有轮速时，长期航向会漂移；IMU 加速度包含重力和偏置，静止时也不能直接得到绝对位置。选择传感器前应先问：目标状态是否可观测？

## 第 2 章：卡尔曼滤波

### 2.1 线性高斯模型

$$x_t=F_tx_{t-1}+B_tu_t+w_t$$

$$z_t=H_tx_t+v_t$$

$w_t\sim\mathcal N(0,Q_t)$ 是过程噪声，$v_t\sim\mathcal N(0,R_t)$ 是测量噪声。

预测：

$$\hat x^-_t=F_t\hat x_{t-1}+B_tu_t$$

$$P^-_t=F_tP_{t-1}F_t^T+Q_t$$

更新：

$$K_t=P^-_tH_t^T(H_tP^-_tH_t^T+R_t)^{-1}$$

$$\hat x_t=\hat x^-_t+K_t(z_t-H_t\hat x^-_t)$$

$$P_t=(I-K_tH_t)P^-_t$$

卡尔曼增益 $K$ 平衡预测和测量。$R$ 大表示不信任测量，$Q$ 大表示不信任模型。调参不能只追求轨迹平滑：过度平滑会增加延迟并掩盖真实运动。

### 2.2 EKF

机器人模型常是非线性的：

$$x_t=f(x_{t-1},u_t)+w_t,\quad z_t=h(x_t)+v_t$$

EKF 在当前估计附近线性化，使用雅可比矩阵：

$$F_t=\frac{\partial f}{\partial x},\quad H_t=\frac{\partial h}{\partial x}$$

线性化误差太大时，EKF 可能不一致甚至发散。初始状态、角度归一化、协方差正定性和时间差都是常见故障点。

### 2.3 一维例子

```python
import numpy as np

x = np.array([[0.0], [0.0]])       # position, velocity
P = np.eye(2)
dt = 0.1
F = np.array([[1.0, dt], [0.0, 1.0]])
H = np.array([[1.0, 0.0]])
Q = np.diag([1e-3, 1e-2])
R = np.array([[0.05 ** 2]])

def step(z):
    global x, P
    x = F @ x
    P = F @ P @ F.T + Q
    innovation = np.array([[z]]) - H @ x
    S = H @ P @ H.T + R
    K = P @ H.T @ np.linalg.inv(S)
    x = x + K @ innovation
    P = (np.eye(2) - K @ H) @ P
    return x.copy()
```

实验时分别扩大 $Q$ 和 $R$，观察响应速度、噪声和滞后。

## 第 3 章：IMU、轮速与多传感器融合

### IMU 测量

陀螺仪测角速度，加速度计测比力。它们存在：

- 白噪声。
- 常值或缓慢变化的偏置。
- 比例因子误差。
- 安装轴不对齐。
- 温度漂移。

角速度积分得到姿态，误差随时间积累；加速度积分两次得到位置，偏置会快速放大。因此 IMU 擅长短期变化，不提供长期绝对约束。

### 轮速里程计

差速机器人左右轮速度 $v_l,v_r$，轮距 $b$：

$$v=(v_r+v_l)/2,\quad \omega=(v_r-v_l)/b$$

轮径或轮距标定错误会形成系统性误差。直线走偏优先检查两侧轮径、编码器方向和控制一致性；旋转角度错误优先检查轮距。

### 融合原则

- 高频 IMU 提供短期动态。
- 轮速提供平面运动约束。
- 激光/视觉里程计提供相对位姿。
- GNSS、AprilTag 或地图定位提供绝对或长期约束。

不要重复融合相关信息。例如视觉里程计已经使用 IMU，再把相同 IMU 与视觉输出当作独立测量融合，会重复计算信息并导致协方差过度自信。

### robot_localization

配置前先画出每个传感器测量哪些状态、属于哪个坐标系、频率和协方差。`two_d_mode` 适用于平面机器人，但仍需正确处理 z、roll、pitch 的输入。

调试时检查：

```bash
ros2 topic hz /imu/data
ros2 topic echo /wheel/odometry --once
ros2 run tf2_ros tf2_echo odom base_link
```

## 第 4 章：SLAM 的结构

SLAM 同时估计机器人轨迹和环境地图。现代系统通常分为：

- **前端**：从传感器数据建立帧间约束。
- **后端**：联合优化历史状态和约束。
- **回环**：识别曾经到过的地点，消除累计漂移。
- **地图管理**：维护点云、栅格、特征或隐式表示。

### 激光前端

二维激光 SLAM 常用扫描匹配，将当前扫描对齐到上一帧或局部地图。环境长走廊、玻璃、动态人群会降低约束质量。

### 视觉前端

特征法提取和匹配关键点；直接法利用像素亮度误差。弱纹理、强光变化、运动模糊会造成跟踪失败。RGB-D 和双目提供尺度，单目需要额外初始化和尺度约束。

### 后端图优化

节点表示位姿，边表示里程计、回环或其他相对约束：

$$X^*=\arg\min_X\sum_{(i,j)}e_{ij}(X)^T\Omega_{ij}e_{ij}(X)$$

$\Omega$ 是信息矩阵，即协方差逆。错误回环是一条高破坏性约束，可能把整个地图拉坏，所以回环需要几何验证和鲁棒核。

## 第 5 章：地图与坐标系

ROS 导航常用：

```text
map → odom → base_link → sensor
```

- `odom → base_link` 连续但会漂移，来自局部里程计。
- `map → odom` 由全局定位或 SLAM 修正，可能发生跳变。
- 控制器依赖连续的 odom，任务目标通常定义在 map。

直接让定位节点发布跳变的 `map → base_link`，控制器可能突然看到速度和位置不连续。

### 栅格地图

每个格子表示占用概率或离散状态：空闲、占用、未知。激光测量可用 inverse sensor model 更新栅格。使用 log-odds 可把乘法贝叶斯更新变为加法。

地图分辨率是精度与成本的折中。分辨率 0.05m 的地图每格代表 5cm；缩小到 0.01m，二维格子数量约增加 25 倍。

## 第 6 章：定位

已有地图时，机器人只需估计位姿。AMCL 使用粒子滤波：

1. 根据运动模型传播粒子。
2. 根据激光与地图一致性赋权。
3. 重采样。

粒子太少可能无法表达多峰分布，太多增加计算。机器人被“绑架”到未知位置时，需要全局重定位或粒子注入机制。

定位质量检查：

- 粒子是否集中。
- 激光点是否与地图墙体对齐。
- 静止时位姿是否抖动。
- 快速运动后能否恢复。
- 初始位姿错误时是否重新收敛。

## 第 7 章：全局路径规划

### 图搜索

Dijkstra 从起点扩展最低累计代价节点，保证非负边权下的最短路径。A* 加入启发式：

$$f(n)=g(n)+h(n)$$

$g$ 是起点到当前节点代价，$h$ 是到目标的估计。若 $h$ 不高估真实代价，A* 保持最优性。

### 栅格上的代价

路径不能只最短，还要远离障碍。常见代价：

$$J=w_lL+w_oC_{obstacle}+w_tC_{turn}$$

膨胀层根据机器人半径和安全距离扩大障碍。机器人实际碰撞而地图路径看似安全，常见原因是 footprint、膨胀半径或地图分辨率错误。

### Hybrid A*

普通栅格 A* 忽略朝向和最小转弯半径。汽车式机器人需要在 $(x,y,\theta)$ 空间搜索，使用满足运动学约束的 motion primitive。

## 第 8 章：局部规划与轨迹控制

全局路径描述宏观路线，局部规划器结合当前速度和局部障碍生成可执行轨迹。它要同时满足：

- 速度、加速度、角速度限制。
- 机器人运动学或动力学。
- 障碍物安全距离。
- 对全局路径和目标的跟踪。

### Pure Pursuit

在路径前方选择前视点，计算曲率跟踪。前视距离小，跟踪紧但易振荡；前视距离大，平滑但转弯切角。可根据速度动态调整前视距离。

### DWB/DWA 思想

在速度空间采样候选，短时模拟轨迹，按障碍、路径、目标等代价评分。采样范围、仿真时间和代价权重共同影响行为。

### 局部最优问题

狭窄通道、U 型障碍、动态人群中局部规划可能振荡或停滞。这不是简单加大某个权重就一定解决，需要结合恢复行为、重新规划和行为树。

## 第 9 章：Nav2 系统

Nav2 不是一个算法，而是插件化导航系统：

- `map_server`：地图服务。
- `amcl`：定位。
- `planner_server`：全局规划。
- `controller_server`：局部控制。
- `behavior_server`：恢复行为。
- `bt_navigator`：行为树编排。
- global/local costmap：环境代价表示。

### 生命周期

Nav2 节点使用 lifecycle：unconfigured、inactive、active、finalized。节点存在但未 active 时不会正常工作。启动失败应检查 lifecycle transition 和参数日志。

### 行为树

行为树把“规划、跟踪、检测失败、清图、旋转、重试”组合成任务逻辑。它解决的是任务级流程，不替代底层规划器。

一个简化流程：

```text
有目标？
  → 计算路径
  → 跟踪路径
  → 失败？清局部代价地图
  → 重新规划
  → 仍失败？旋转/后退
  → 超过次数则报告失败
```

## 第 10 章：系统调试与评估

### 分层排查

1. 传感器频率、时间戳、数据值。
2. TF 树和坐标方向。
3. 里程计连续性和尺度。
4. 地图质量与定位对齐。
5. footprint、代价地图、膨胀层。
6. 全局路径是否合理。
7. 局部轨迹和速度命令。
8. 控制器是否真实执行。

### 自动化导航评估

单次成功没有统计意义。固定地图，生成一组起终点，重复运行并记录：

- 成功率。
- 规划时间。
- 实际路径长度/最短路径长度。
- 到达时间。
- 最小障碍距离。
- 恢复行为次数。
- 最终位置和角度误差。

```python
result = {
    'start': [0.0, 0.0, 0.0],
    'goal': [4.0, 2.0, 1.57],
    'success': True,
    'planning_ms': 18.4,
    'travel_time_s': 26.3,
    'path_length_m': 5.7,
    'min_clearance_m': 0.31,
    'recoveries': 1,
}
```

### 第三册阶段项目

构建一个仿真移动机器人导航系统：

- 差速底盘、激光、IMU、轮速。
- EKF 融合里程计。
- SLAM 建图与 AMCL 定位。
- Nav2 全局/局部规划。
- 自动执行至少 20 组起终点。
- 输出 CSV 报告和失败分类。

合格标准：成功率不低于 85%；每个失败都能归类到定位、规划、控制、碰撞或超时；所有参数和地图纳入版本管理；可用 rosbag 回放复现至少一个失败案例。
