# 第六册实验与验收

## 实验 1：可靠 GPU 基准

选择一个视觉模型，测量 batch 1/4/8，FP32/BF16，输入尺寸 224/512。每组 warmup 50 次，正式运行 500 次。

记录 mean、P50、P95、P99、FPS、显存。保存原始延迟数组，而不是只复制终端平均值。

故意去掉 `torch.cuda.synchronize()`，比较错误计时结果并解释原因。

## 实验 2：数据管线分析

分别测量：读取、JPEG 解码、resize、归一化、H2D、模型、后处理。测试 `num_workers`、pinned memory 和预取。

验收：能用时间线证明瓶颈在 CPU、拷贝还是 GPU，而不是根据利用率主观猜测。

## 实验 3：PyTorch Profiler

导出 trace，回答：

- CUDA 时间最长的三个算子。
- CPU 与 GPU 之间最大空闲段。
- 是否存在频繁同步。
- 哪个操作分配显存最多。
- shape 是否符合预期。

提出一个优化并重新测量，若指标无改善，应保留失败记录。

## 实验 4：ONNX 一致性

准备：随机输入、真实图片、全黑、全白、最大/最小尺寸。比较 PyTorch 与 ONNX 输出：

```python
max_abs = np.max(np.abs(torch_out - onnx_out))
mean_abs = np.mean(np.abs(torch_out - onnx_out))
```

分类比较 top-1，检测比较框、置信度和 NMS 后结果。不要只检查一张图片。

## 实验 5：TensorRT 精度与性能

构建 FP16 engine；有代表性数据时再构建 INT8。比较：

- engine 构建时间和大小。
- 首次/稳定延迟。
- 显存。
- 任务指标。
- 动态 shape 性能。

若 INT8 快但任务指标明显下降，应分析敏感层和校准数据，而不是直接宣布优化成功。

## 实验 6：ROS2 端到端延迟

在消息中携带采集时间，分别记录进入回调、预处理结束、推理结束、发布时间。统计 10 分钟。

测试：正常负载、CPU 压力、GPU 压力、输入频率高于处理频率。检查队列是否持续增长。

## 实验 7：故障恢复

注入：相机停止、错误尺寸、模型文件损坏、输出 NaN、GPU OOM、推理超时。系统必须发布健康状态，停止危险输出，并按策略重试或退出。

## 实验 8：一小时稳定性

记录每分钟：RSS、显存、温度、功耗、P95 延迟、输入输出频率。内存持续单调增长说明可能泄漏；温度导致频率下降会改变尾延迟。

## 发布验收表

| 项目 | 必须满足 |
| --- | --- |
| 正确性 | 与 PyTorch 基线在定义容差内 |
| 延迟 | P95 小于系统周期预算 |
| 稳定性 | 连续运行一小时无持续资源增长 |
| 输入异常 | 可检测且不发布危险输出 |
| 可复现 | 锁定版本、模型校验和、构建脚本 |
| 可观测 | 分阶段延迟、频率、健康状态 |
| 回归 | 固定 rosbag 可自动比较 |
| 文档 | 接口、单位、坐标系和限制完整 |
